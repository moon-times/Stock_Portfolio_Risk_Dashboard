## 1. 배경

개인 투자자는 증권사 MTS에서 **개별 종목의 수익률**은 쉽게 확인할 수 있지만, **포트폴리오 전체가 얼마나 위험한지**는 알기 어렵다. MTS는 "삼성전자 +2.3%"는 보여주지만 "내 포트폴리오는 국내주식과 해외주식의 상관계수가 0.62라 분산이 사실상 되어 있지 않다"는 말은 해주지 않는다.

리스크 지표(변동성, 샤프지수, MDD, VaR, 상관관계)는 계산 자체는 표준화되어 있으나,

1. 계산에 필요한 데이터를 모으는 과정이 번거롭고
2. 계산 결과가 숫자로만 나와서 **무엇을 해야 하는지 해석이 안 된다**

이 프로젝트는 토스증권 Open API로 실제 보유 자산을 가져와 리스크 지표를 자동 계산하고, LLM이 그 숫자를 **자연어 진단으로 번역**해주는 로컬 대시보드를 만든다.

## 2. 문제 정의

| # | 문제 | 현재 상태 | 목표 상태 |
|---|---|---|---|
| P1 | 자산배분 현황을 한눈에 못 봄 | 종목 리스트만 나열됨 | 자산군/섹터별 도넛 차트 |
| P2 | 리스크 수치를 알 수 없음 | 제공 안 됨 | 변동성·샤프·MDD·VaR 자동 계산 |
| P3 | 숫자를 봐도 해석이 안 됨 | 사용자가 직접 판단 | LLM이 진단 코멘트 생성 |
| P4 | 분산 효과 착시 | 종목 수가 많으면 분산됐다고 착각 | 상관관계 히트맵으로 실제 분산도 확인 |

## 3. 목표 및 비목표

### 3.1 목표 (Goals)

- **G1**: 토스증권 Open API로 실계좌 보유 종목·잔고를 조회해 자산배분을 시각화한다.
- **G2**: 표준 리스크 지표 4종 이상(연변동성, 샤프지수, MDD, VaR)을 자동 계산해 표시한다.
- **G3**: 자산군 간 상관관계를 히트맵으로 제시해 실질 분산 수준을 드러낸다.
- **G4**: 계산된 지표를 근거로 LLM이 3문장 내외의 진단 코멘트를 생성한다.
- **G5**: 로컬에서 `streamlit run app.py` 한 줄로 실행되어 시연 가능한 상태를 만든다.

### 3.2 비목표 (Non-Goals)

명시적으로 **이번 MVP에서 하지 않는 것**. Claude Code는 아래 항목을 자발적으로 구현하지 않는다.

- ❌ 매매 주문 실행 (조회 전용, 주문 API 호출 금지)
- ❌ 리밸런싱 시뮬레이터 (v2 후보)
- ❌ 시나리오 스트레스 테스트 (v2 후보)
- ❌ 다중 계좌 / 다중 증권사 통합
- ❌ 사용자 인증 · 회원가입 · 멀티 유저
- ❌ 클라우드 배포 (Streamlit Cloud 등)
- ❌ 실시간 스트리밍 시세 (WebSocket `wss://openapi-ws.tossinvest.com/ws/v1`)
- ❌ 주문 내역·체결 내역 조회 (`GET /api/v1/orders`)
- ❌ 조건주문 등록·조회
- ❌ 옵션·선물 등 파생상품 리스크 모델링
- ❌ 자동 알림 (텔레그램/디스코드 웹훅)

## 5. MVP 범위 (In Scope)

### 5.1 핵심 기능 4종

| ID | 기능 | 설명 | 우선순위 |
|---|---|---|---|
| F1 | 계좌 연동 및 잔고 조회 | 토스증권 API로 보유 종목·수량·평가금액 조회 | P0 |
| F2 | 자산배분 시각화 | 자산군별 도넛 차트 + 비중 범례 | P0 |
| F3 | 리스크 지표 계산 | 연변동성, 샤프지수(국채 실시간 금리), MDD, VaR(95%), 베타, HHI | P0 |
| F4 | AI 진단 코멘트 | Claude API로 지표 기반 자연어 진단 생성 | P0 |
| F5 | 상관관계 히트맵 | 자산군 간 상관계수 행렬 | P1 |
| F6 | 벤치마크 비교 차트 | 포트폴리오 vs KOSPI 지수화 라인 차트 | P1 |

P0는 반드시 완성, P1은 시간이 남으면 완성. **P1이 미완이어도 데모는 성립해야 한다.**

### 5.2 UI 레퍼런스

전체 레이아웃은 `docs/assets/dashboard_mockup.png`를 기준으로 한다.

![대시보드 목업](assets/dashboard_mockup.png)

레이아웃 구조(위 → 아래):

1. **헤더**: 제목 + 데이터 기준 시각
2. **메트릭 카드 4개** (가로 1열): 총 자산가치 / 일간 손익 / 샤프지수 / MDD
3. **2단 카드**: 좌측 자산배분 도넛 + 범례, 우측 리스크 지표 테이블
4. **상관관계 히트맵** (전폭)
5. **벤치마크 비교 라인 차트** (전폭)
6. **AI 진단 코멘트 배너** (전폭, 연한 파란 배경)

> 목업은 **레이아웃과 정보 위계의 기준**이지 픽셀 단위 사양이 아니다. Streamlit 기본 컴포넌트로 동일한 정보 배치를 재현하는 것이 목표이며, 목업의 색상·간격을 CSS로 정밀 복제할 필요는 없다.

## 7. 성공 지표

### 7.1 기능적 성공 기준 (데모 통과 조건)

- [ ] `streamlit run app.py` 실행 후 브라우저에서 대시보드가 렌더링된다
- [ ] 실계좌 보유 종목이 도넛 차트에 반영된다
- [ ] 리스크 지표 4종이 `N/A` 없이 숫자로 표시된다
- [ ] AI 코멘트가 실제 계산값을 인용한 문장으로 생성된다
- [ ] 전체 로딩 시간이 15초 이내다 (캔들 20콜 + 스로틀 포함)
- [ ] 앱을 2회 연속 실행해도 토큰이 재발급되지 않는다
- [ ] 20종목 연속 조회에서 429가 발생하지 않는다
- [ ] API 키 없이 실행해도 샘플 데이터로 화면이 뜬다 (폴백 검증)

### 7.2 품질 기준

- 리스크 계산 함수는 단위 테스트로 검증한다 (알려진 입력 → 알려진 출력)
- API 키·시크릿은 코드·스크린샷·git 히스토리 어디에도 노출되지 않는다
