명세(또는 지금까지의 대화)를 **티켓**으로 쪼갠다.

## 티켓이란

**혼자서도 눈으로 확인되는, 세로로 얇게 자른 한 조각.**

- 화면·저장·처리를 **전부 관통**한다. "화면만 먼저" 는 티켓이 아니다
- 그 티켓 하나만 끝내도 **뭔가가 실제로 돌아간다**
- **한 번의 대화 안에서** 끝날 크기다. 안 끝날 것 같으면 더 쪼갠다
- 학생 프로젝트 기준으로 **전체 3~6개**가 적당하다. 10개가 넘으면 쪼개기가 과하다

## 절차

### 1. 재료를 모은다

사용자가 파일 경로를 줬으면 그 파일을 읽는다. 안 줬으면 `specs/` 안의 명세를 찾아 읽는다.

### 2. 세로 조각으로 나눈다

각 티켓에 **막고 있는 티켓(Blocked by)** 을 적는다. 아무것도 막지 않는 티켓은 지금 바로 시작할 수 있다.

**1번 티켓은 반드시 "가장 앙상하지만 끝까지 돌아가는 한 줄"이어야 한다.** 화면 하나에 입력 하나, 결과 하나. 예쁘게 만들지 않는다.

### 3. 확인 방법을 Given / When / Then 으로 쓴다

각 티켓의 확인 항목은 **반드시** 이 세 줄 형식이다. 형용사를 쓰지 않는다.

```
- [ ] Given 저장된 항목이 하나도 없는 상태에서
      When  입력창에 "달걀"을 치고 엔터를 누르면
      Then  목록에 "달걀" 한 줄이 보인다
```

나쁜 예: `- [ ] 목록이 잘 나온다` ← **"잘"은 확인할 수 없다. 이런 줄은 쓰지 않는다.**

한 티켓에 확인 항목은 **2~4개**. 그보다 많으면 티켓이 큰 것이다.

### 4. 사용자에게 보여주고 묻는다

번호 목록으로 제시한 뒤 이 세 가지를 묻는다.

- 크기가 맞나 — 너무 크거나 너무 잘게 쪼개지지 않았나
- 1번 티켓만 끝나도 **화면에서 뭔가 보이나**
- 합칠 것이나 더 쪼갤 것이 있나

사용자가 승인할 때까지 고친다. **승인 전에는 파일을 쓰지 않는다.**

### 5. 파일로 저장한다

프로젝트 루트에 `tickets.md` 로 저장한다. 이미 있으면 **덮어쓰지 말고 아래에 이어 붙인다.**

<티켓-파일-템플릿>

# 티켓 — <무엇을 만드는가>

한 줄 요약. 어느 명세에서 나왔는지 파일 이름을 적는다.

**막힌 게 없는 티켓부터 하나씩** 한다. 하나 끝날 때마다 `/clear` 하고 다음으로 간다.

## 1. <티켓 제목>

**무엇이 돌아가게 되나:** 사용자 입장에서 한두 문장.

**막고 있는 것:** 없음 — 바로 시작 가능

- [ ] Given …
      When  …
      Then  …
- [ ] Given …
      When  …
      Then  …

## 2. <티켓 제목>

**막고 있는 것:** 1번

…

</티켓-파일-템플릿>

파일 경로를 알려주고 한 줄 덧붙인다 —
**"1번 티켓을 만들려면 `/implement 1번 티켓` 을 치세요."**
